# 评审准入标准

只有同时满足下面条件，才建议进入自动化生成阶段：

- 需求范围相对稳定
- 核心业务流已完整拆解
- 总览图可以在一屏内解释清楚核心模块关系
- 模块图已经把主路径、异常、边界、权限拆开，单图不过载
- 测试矩阵可以追踪到主要需求点和测试意图
- 关键角色和权限差异已说明
- 主要异常和边界已覆盖
- 待澄清项数量可控，且不阻塞主路径设计
- 冲突项已给出处或已明确需要产品/研发裁决

## 评审结论分级

- `通过`
  可以进入 API/UI/Load Creator skill
- `有条件通过`
  可以进入下一阶段，但必须在产物中保留限制条件
- `不通过`
  先补需求或重新评审，不进入自动化生成

## 常见不通过原因

- 用例只覆盖 happy path
- 总览图或模块图过于拥挤，评审无法快速建立结构感
- 缺少测试矩阵，导致图和用例不可追踪
- 权限差异未说明
- 核心状态流转未明确
- 测试数据依赖缺失
- 待澄清项直接影响接口或页面行为
