# 需求分析参考

按下面顺序分析需求，避免直接进入写用例：

1. 明确业务目标
2. 识别核心角色
3. 列出关键对象和状态
4. 找出关键操作和状态流转
5. 找出异常、边界、权限差异
6. 找出依赖系统、测试数据、人工前提

## 需求拆解清单

- 模块：有哪些独立业务域或页面域
- 角色：哪些角色参与，权限是否不同
- 对象：订单、任务、申请单、报表等核心对象是什么
- 状态：对象如何创建、更新、流转、终止
- 规则：哪些校验和约束是明确写出的
- 异常：哪些失败场景被显式描述
- 非功能：是否存在性能、安全、审计、兼容性要求

## 高风险信号

- 一个动词对应多种系统行为，但需求未区分条件
- 同一字段在不同章节定义不一致
- 页面文案和接口行为不一致
- 只有结果描述，没有前提条件
- 需求提到“自动”“实时”“异步”，却没有解释触发机制

## 产出前检查

- 每条重要需求是否至少映射到一个可验证场景
- 每个关键场景是否能看出角色、前置条件、主路径、异常路径
- 每个待澄清项是否都能说明为什么影响测试设计
